# 改配置手册

> 这份手册解决一件事：**以后配置要改，你自己能改。**
> 里面的命令都可以直接复制执行。看不懂的地方不用硬扛，把报错发我。

---

## 0. 先搞清楚：什么能自动，什么不能

| 改动 | 频率 | 怎么做 | 自动化 |
|---|---|---|---|
| 加一个新期刊 | 偶尔 | 一条命令 | ✅ 全自动 |
| 改字体 / 字号 | 很少 | Word 改模板 + 一条命令推送 | 🟡 半自动 |
| 加/删/调换章节 | 每篇不同 | 改两个地方 | ❌ 手动 |
| 改导出设置（编号/目录/页边距） | 偶尔 | 改 yaml | ❌ 手动 |

**为什么后两项不能自动**：它们直接影响论文内容长什么样，不同论文要求不一样。脚本替你改，改错了你很难发现。

---

## 1. 加一个新期刊（全自动）

### 第一步：拿到 CSL 文件

1. 打开 <https://www.zotero.org/styles>
2. 搜索期刊全名，例如 `Chemosphere`
3. 点进去，下载 `.csl` 文件（会存到「下载」文件夹）

> CSL 决定参考文献的格式。找不到完全同名的，就选出版社的通用样式
> （ACS、Elsevier 的通用样式），遇到问题再换。

### 第二步：一条命令

```bash
cdp _template
bash tools/add-journal.sh chemosphere ~/Downloads/chemosphere.csl
```

- 第一个参数是你自己取的简称（以后 `bash build.sh chemosphere` 就用它）
- 第二个参数是上一步下载的文件路径

脚本会自动：把 CSL 放进 `assets/csl/`、生成 `assets/journals/chemosphere.yaml`、**同步到所有论文仓库**。

### 第三步：提交改动

打开 GitHub Desktop，逐个仓库点一下 Commit（`paper-1`、`paper-2`……）。
脚本会告诉你有哪几个仓库被改了。

### 也可以直接给网址

```bash
bash tools/add-journal.sh chemosphere https://raw.githubusercontent.com/citation-style-library/styles/master/chemosphere.csl
```

不推荐——国内网络经常下不动，手动下载更稳。

## 2. 改字体（半自动）

**原理**：Word 的字体只由 `assets/reference.docx` 里面的「样式」决定。**改 Markdown 或 MarkText 的字体没有任何用。**

### 第一步：改母版

1. 在 Finder 里打开 `_template/assets/reference.docx`（用 Word）
2. 菜单「格式 → 样式」或直接改：
   - `Normal` → 中文宋体、西文 Times New Roman、小四
   - `Heading 1/2/3` → 中文黑体
   - `Caption` → 图注字号
3. 保存关闭

### 第二步：推送

```bash
cdp _template
bash tools/sync-config.sh
```

### 第三步：重新导出

进入每篇论文跑一次 `bash build.sh`，或者看 GitHub Desktop 里改了哪些仓库，逐个提交。

### ⚠️ 千万不要跑这条

```bash
pandoc -o assets/reference.docx --print-default-data-file reference.docx
```

它会把模板覆盖成 Pandoc 的空白默认值，字体全部丢失。

## 3. 改章节结构（手动）

每篇论文可能不一样，**只改那篇自己，不要动 `_template`**。

### 加一节

**① 新建文件**：在 `manuscript/` 下建，例如 `05-discussion.md`，第一行写标题：

```markdown
# Discussion

正文……
```

**② 加进导出列表**：编辑 `assets/export-common.yaml`，在 `input-files:` 下面按顺序加一行：

```yaml
input-files:
  - manuscript/00-front.md
  - manuscript/01-intro.md
  - manuscript/02-methods.md
  - manuscript/03-results.md
  - manuscript/05-discussion.md      ← 新加的，位置决定它在论文里的位置
  - manuscript/04-conclusion.md
```

**漏了第 ② 步 = 新文件不会出现在导出结果里**，这是最常见的错。

### 删一节

1. 从 `export-common.yaml` 里删掉那一行
2. 文件可以留着（不参与导出），也可以删

### 只是调顺序

**只改 `export-common.yaml` 里的行序**，不用动文件名，也不用动文件内容。

### 数字前缀是干什么的

`00-`、`01-`、`90-` 只是让文件在 Finder 里排序好看，**不决定论文里的顺序**。顺序只看 yaml 里 `input-files:` 的排列。

## 4. 改导出设置（手动）

| 想改什么 | 改哪个文件 | 加什么 |
|---|---|---|
| Word 里要不要目录 | `assets/export-word.yaml` | `table-of-contents: true/false` |
| 目录显示到几级 | 同上 | `toc-depth: 3` |
| 章节要不要编号 | `assets/export-common.yaml` | `number-sections: true/false` |
| 页面边距 | `assets/export-latex.yaml` | `geometry: margin=2.5cm` |
| 导言区加载宏包 | `assets/texpage-template.tex` | `\usepackage{...}` |

**这些文件不在同步范围内**（`sync-config.sh` 不会碰），所以每篇论文可以有自己的设置。

## 5. 同步机制：哪些会被覆盖

每个仓库根目录有个 `.kit` 文件，写着 `paper` 或 `thesis`。

`bash tools/sync-config.sh` 只同步给写着 `paper` 的仓库，**`thesis` 完全不受影响**。

| 会被同步 / 覆盖 | 不会被碰 |
|---|---|
| `assets/journals/` | `manuscript/`（全部正文） |
| `assets/csl/` | `assets/export-*.yaml` |
| `assets/reference.docx` | `assets/metadata.yaml` |
| `build.sh` `build.ps1` | `assets/texpage-template.tex` |
| `.gitignore` `.gitattributes` | `RELEASES.md` |
| `new-paper.sh/ps1` | |

同步后每个仓库会显示改动。**检查后再提交**，不满意就丢弃（见下一节）。

先看看会改什么、不真改：

```bash
cdp _template
bash tools/sync-config.sh --dry-run
```

## 6. 改错了怎么退

### 还没提交

**GitHub Desktop**：左边 `Changes` 里，右键某个文件 → `Discard changes`

或者终端：

```bash
cdp paper-1
git restore .                       # 丢弃所有未提交改动
git restore assets/export-common.yaml   # 只丢弃某一个文件
```

### 已经提交了

**GitHub Desktop**：点 `History` → 找到那条提交 → 右键 `Revert changes in commit`

或者终端：

```bash
git revert <提交哈希>
```

### 彻底乱了，想回到某个版本

```bash
git log --oneline          # 找到要回到的那一版
git restore --source=<哈希> --worktree -- .    # 只取回文件内容，不改历史
```

## 7. 三条不要做的事

1. **不要在 `_template` 里写稿。** 它是母版，只放配置。
2. **不要把正在写的论文仓库复制出去当模板。** 会把历史一起带过去。新建一律用 `_template` 或 `bash new-paper.sh`。
3. **不要手动删 `.git` 文件夹。** 那是全部历史。要删整篇论文，删整个文件夹就行。

## 8. 脚本报错时

把终端里的完整输出发我，包括最后那行 `Error:` 或 `curl:` 开头的。

最常见的两种：

| 报错 | 原因 |
|---|---|
| `curl: (35)` / `(7)` | 网络或代理问题，改成手动下载 CSL 再传本地路径 |
| `未知期刊: xxx` | 简称打错了，或者那个期刊还没加，看 `assets/journals/` 里有什么 |
